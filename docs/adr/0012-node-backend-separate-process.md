# 12. Node backend in a separate process

- Status: Accepted
- Date: 2026-11-24

## Context

The Hub is gateway-centric: its server mainly routes MCP traffic, talks to provider CLIs and serves the UI. The agent and MCP SDKs are strongest in TypeScript, and the UI is already TypeScript. A Java server (ADR 3) means a second language, a bundled JRE (ADR 8) and a heavier installer for little gain. The backend must keep running while the window is closed, and a crash must not take the UI down.

## Decision

Write the Hub server in Node/TypeScript (Fastify) and run it as a separate OS process:

- Electron main starts `server/` with `utilityProcess.fork`, waits for a `ready` message with the port, and stops it on quit. The backend also exits when the parent channel closes.
- The backend listens on `127.0.0.1`, port `0` only.
- Main generates a random session secret and sends it over the parent channel, never on the command line. Every API route requires `Authorization: Bearer <secret>`.
- The API is contract-first: `api/openapi.yaml` is the source of truth, with types generated by `openapi-typescript` and calls made through `openapi-fetch`.
- The renderer never holds the secret or the port. Its client sends requests over IPC; main checks the path is relative, adds the bearer header and calls the backend.
- `server/` does not import `electron`; only the launcher adapter in `ui/` does.

## Consequences

- ADR 3 no longer applies to the Hub server; Spring Boot remains the choice for the separate MCP server project.
- ADR 6: SQLite and sqlite-vec stay. Tika and LangChain4j need Node replacements, decided in a later change.
- ADR 7: LangGraph4j becomes LangGraph.js, decided later.
- ADR 8: a bundled JRE is only needed for future local MCP servers, not for the Hub.
- ADR 9: the contract stays. The client is generated with `openapi-typescript` and `openapi-fetch`, and UI calls go through Electron main.
- ADR 11: `server/` is a Node package, not Spring Boot modules.
- Streaming responses (future chat) need an IPC streaming channel.
- ADRs 1–11 still live in the docs repo until the `move-hub-adrs` change moves them here. New Hub ADRs start at 12 in `docs/adr/`.
